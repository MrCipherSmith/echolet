# Acceptance criteria

- AC1: A person completes registration from inside the console alone, without typing a CLI command in another terminal: an identity is created, the publication pool is published, their own card is exported, a peer's card is imported and pinned, and the result is confirmed. Demonstrated against a real driven CLI process, not only the pure layer.
- AC2: A message is composed and sent from the console to a pinned contact, and what the console shows afterwards is what the store holds — not an optimistic local echo. Demonstrated against a real driven process.
- AC3: The plaintext body of a message never appears in the argv or environment of any child the console spawns. `send` accepts the body on stdin, the console uses that path and only that path, and a test asserts the complete argv of every spawned child and fails if a body appears anywhere in it. `--text` **stays accepted by the CLI**: nine call sites in the operator's live prototype scripts use it, and breaking a running prototype to close a hazard that only affects callers who choose it is not this wave's trade to make. Its argv exposure is documented where the command is documented, and whether to retire it is recorded as an open decision for the user, not settled here.
- AC4: The address book lists every pinned correspondent with its trust state, visibly distinguishes pinned from unpinned and from expired, and shows the four out-of-band comparison values in full for the selected entry — never elided, at any viewport where the entry can be selected.
- AC5: Every exit class the CLI can return (2 configuration, 3 trust, 4 relay, 5 persistence) is presented with a message that is accurate for the command that produced it, and the console never reports a class the CLI did not return. Totality is proven over the command × exit-class matrix, not sampled.
- AC6: The properties flows 002 and 003 established are re-verified unchanged on the final tree: `renderFrame` stays pure, total, deterministic, escape-free and exactly rows by cols; no key material appears in any frame or child argv; the unaudited-prototype notice appears on every frame; one command is in flight at a time; and the trust modal cannot confirm what was never painted.
- AC7: Text the operator types cannot put a control character or an escape sequence into a frame. Proven over arbitrary input at the reducer boundary, not by filtering inside the renderer — the property must belong to the state, not to the renderer's defensiveness.
- AC8: Nothing the console can do denies the operator a way out: at any viewport, and in any state including a command in flight and a modal open, the key that quits is either available or the console says why it is not.
- AC9: No test is weakened, skipped, narrowed or deleted to reach any of the above, and every fix lands after a test that failed for the right reason first, with the ordering provable from the git history.
- AC10: A live run against the real relay on the tailnet, with the second user on `depr`, is recorded: registration, a message sent and a message received, in both directions. The record states what worked and what did not, and any step that still needed a terminal outside the console is named as a miss against AC1.
